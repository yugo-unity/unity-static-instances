# Static Instances Graphics Settings

これらの設定で、プロジェクト全体の SIS の品質とビルドのポリシーを構成します。
個々のオーナーの可視性、LOD ラダー、Draw Range については
[Static Instance Scatter Inspector](StaticInstanceScatterInspector.ja.md) を使用します。
最初のシーンは[ユーザーガイド](UserGuide.ja.md)から始めてください。

## 設定を開く

**Edit > Project Settings > Graphics** を開き、URP の設定内にある **Static Instances** を
探します。最初に品質のセクションがあり、その後にオペレーションウィンドウのボタン、
ベイクのポリシー、ストリッピングのポリシーが続きます。

以下の既定値は、新規作成された設定のものです。既存の設定は保存済みの値を保持します。
ほとんどの品質設定は Play Mode 中に編集しても適用されます。**Cull Distance Scale** は
カリングデータを再構築します。これらはフレームごとにアニメーションさせる制御として
使えるものではありません。

## LOD

| 設定 | 用途 |
| --- | --- |
| **Min Level** | プロジェクト全体の最小メッシュ LOD レベルで、**0** から **3**、既定値は **0** です。レベルが高いほど粗くなります。各オーナーの最小値と組み合わされ、利用可能な範囲内でより粗い方の最小値が優先されます。メッシュレベルを生成したり、遷移距離を書き換えたりはしません。 |
| **Distance Scale** | サポートされる LOD 距離に乗算します。既定値は **1**、Inspector での範囲は **0.25–2** です。1 未満ではより早く粗いディテールに切り替わり、1 より大きいとより遠くまでディテールを保持します。 |
| **LOD Bias** | LOD とスケーラブルな Draw Range の距離に対する、SI 専用の追加の乗数です。既定値は **1**、Inspector での範囲は **0.25–2** です。Distance Scale と合成され、Unity の `QualitySettings.lodBias` とは独立しています。 |

Screen Size による選択は、オーサリングした割合とカメラの FOV を引き続き使用します。
その絶対値の Draw Range Min/Max の境界は、これらの乗数に関わらず絶対値のままです。
Distance モードのスケーラブルな制限には SI の LOD Bias が含まれます。距離の上限を
決める前に、Inspector の
[Draw Range](StaticInstanceScatterInspector.ja.md#draw-range-の距離の解釈) のリファレンスを
確認してください。プロジェクトの品質を変更しても、すべての種類の境界が同じように
スケールするわけではありません。

## Fade

| 設定 | 用途 |
| --- | --- |
| **Enabled** | SIS のディザーフェードのマスタースイッチで、既定値は**オン**です。オフにすると、各オーナーのオーサリング済みの Fade Mode は保持したまま、メッシュ LOD と Draw Range の遷移が即時切り替えになります。オンにするとオーサリング済みのモードが許可されますが、オーナーの **None** モードを上書きすることはありません。 |
| **Duration** | **Time** フェードの既定の秒数で、既定値は **0.5**、Inspector での範囲は **0–1** です。オーナーの **Fade Duration** が 0 の場合に使われます。オーナーの duration が 0 以外ならそちらが優先されます。 |
| **Curve** | 時間駆動と距離駆動の両方のディザーフェードのカーブ形状です。既定は **Linear** で、**Sine Ease** は両端を滑らかにします。変わるのはブレンドの形状であり、選択されるレベルやカリング境界は変わりません。 |

> [!NOTE]
> アクティブな URP Asset でも **LOD Cross Fade** を有効にする必要があります。有効でない場合、
> この設定がオンでも実効的なフェードは無効になります。オーナーの LOD を強制すると
> メッシュ LOD のフェードは無効になりますが、Draw Range のフェードがそれに伴って無効に
> なることはありません。

## Size-Based Culling

| 設定 | 用途 |
| --- | --- |
| **Cull Distance Scale** | ベイク済みインスタンスのサイズ 1 単位あたりの距離です。既定値の **0** はこの遠方カリングを無効にします。Inspector での範囲は **0–100** です。Distance モードのオーナーは、各インスタンスのバウンディングスフィアの直径と形状補正から遠方のしきい値を導出します。導出されたしきい値の方が小さければ、オーサリングした Draw Range Max より手前でカリングされることがあります。スケールを変更するとカリングデータが再構築されるため、オーサリング時や頻度の低い品質変更に使ってください。 |
| **Derived Cull Fade Fraction** | サイズから導出された遠方の制限 (Screen Size の **Culled** 比率を含む) が **Distance** フェードを決定する場合の、空間的なフェード帯の割合です。既定値は **0.15**、Inspector での範囲は **0–0.5** です。解決された制限が 700 m の場合、0.15 で約 105 m の帯になります。0 にするとこの空間的な帯はなくなります。Time フェードは代わりに duration を使い、None は即時にカットします。 |

**Cull Distance Scale** は、メッシュ LOD が無効であっても **Screen Size** を使うオーナーには
影響しません。代わりにオーナーの **Culled** 比率か、明示的な Draw Range Max を使ってください。
Screen Size の比率から導出された遠方の制限が優先される場合も、**Derived Cull Fade Fraction**
は Distance フェードの帯を供給します。
オーサリングした制限と導出された制限が Distance モードで共存する場合、実効的なしきい値が
小さい方が優先されます。等しい場合は、オーサリングした制限がフェード幅を供給します。
オーサリングした近方の境界は、Derived Cull Fade Fraction ではなくオーナーの Fade Width を
使用します。

サイズベースのカリングは、除外されたインスタンスの数ではなく、描画結果を見て調整して
ください。薄いオブジェクトや平たいオブジェクトは、補正後のサイズが小さくても重要な
シルエットや目に見える構造を形作っていることがあるため、強すぎる設定では舗装、葉のシート、
旗などの面が早すぎるタイミングで消えることがあります。プロジェクト全体のスケールを
採用する前に、代表的なビューと距離で確認し、影響を受けるピクセルとシルエットで判断して
ください。

## Camera

| 設定 | 用途 |
| --- | --- |
| **FOV Tracking** | **Distance** モードの境界に対する任意の FOV 補正で、既定値は**オフ**です。各オーナーの **Reference FOV** を使用します。透視投影カメラの FOV を狭めると、オーサリングした遠方範囲を含むスケーラブルな境界が延長されます。Screen Size はこのスイッチとは関係なくカメラの FOV を反映します。 |

オーナーの基準値はオーサリングした値であり、Camera.main とライブで連動するものでは
ありません。Distance モードは、正投影のビューや使用できない FOV のビューには FOV 補正を
適用しません。Screen Size モードは、そうしたビューでは保存されている基準 FOV に
フォールバックします。これは正投影カメラのサイズに基づくモデルではありません。
FOV Tracking を有効にするとズーム時により多くのジオメトリが残る場合があるため、品質と
コストのトレードオフをご自身のコンテンツで評価してください。

## Shadows

| 設定 | 用途 |
| --- | --- |
| **Receiver Sphere Cull** | 既定値は**オン**です。シャドウレシーバーに届き得ないシャドウキャスターを、クラスターと個々のインスタンスの両方のレベルで除外します。オーナーの **Cast Shadows** と **Shadow Cast Max Level** とは独立しています。効果はビューとレシーバーのカバー範囲に依存し、すべてのシーンで高速化が保証されるわけではありません。 |

## SpeedTree コンテンツ

SpeedTree の風に関する設定はありません。SIS は風をシミュレーションしません。マテリアルが
SpeedTree の風キーワードを有効にしているベイク済みの描画グループに対し、
[オペレーションウィンドウ](OperationsWindow.ja.md)の明示的なベイク操作は風を取り除いた
クローンマテリアルを生成し、SIS はそのクローンを描画します。これにより SpeedTree の木は
風の頂点処理コストなしで静止状態で描画されます。クローンが生成されていないグループは
元のマテリアルを使い続け、静止状態で描画されますが、風の頂点処理コストは引き続きかかります。

## 操作とベイクのポリシー

| 設定 | 用途 |
| --- | --- |
| **Open Operations Window** | 検証、ベイク、変換、シーン処理を行う [Static Instances オペレーションウィンドウ](OperationsWindow.ja.md)を開きます。クリックしてもベイクは開始しません。 |
| **Bake On Entering Play Mode** | 既定値は**オン**です。通常の Play の前に、開いているシーン内の未ベイク/古い対象を再ベイクします。シリアライズされたオーサリングデータが変わるため、シーンは未保存状態になり、保存するか破棄するかはユーザーが判断します。Bake On Build とは独立しています。オフにしても既存のベイクは消去されません。 |
| **Bake On Build** | 既定値は**オン**です。ビルドパイプラインが扱うシーンのコピー上で未ベイク/古い対象を修復し、変更をオーサリング用のシーンアセットに保存し戻すことはありません。 |

Bake On Build を無効にすると、未ベイクのコンテンツはランタイムで収集されるため、
ロード時のアロケーションと処理が発生し、ソースも保持されます。ベイク済みでも古い対象は、
通常の Player ビルドで依然としてエラーになります。ランタイムでは Editor のアセットハッシュに
よる検証を行えないためです。ビルドエラーを解消するか再ベイクしてください。このポリシーを
無効にしても、古いキャッシュを回避する手段にはなりません。

## ストリッピングのポリシー

| 設定 | 用途 |
| --- | --- |
| **Strip Baked Sources On Build** | 既定値は**オン**です。必要な物理/ゲームプレイ用のオブジェクトは保持したまま、出力されるシーンから冗長なベイク済みの描画ソースを削除します。オーサリング用のシーンはストリップしません。元の MeshRenderer が必要な比較用のビルドでは無効にしてください。その場合、それらのソースをロードするため、ソースのストリッピングによるロード面の利点は失われます。 |
| **Strip Unused Dots Instancing Variants** | 既定値は**オン**です。出力される SIS コンテンツと追加のシェーダーリストに基づき、未使用の `DOTS_INSTANCING_ON` シェーダーバリアントを削除します。ビルドが参照するすべてのレンダーパイプラインアセットで GPU Resident Drawer が無効な場合にのみ適用されます。ソースのストリッピングとは独立しています。 |
| **Additional Dots Instancing Shaders** | ストリッピング後も DOTS インスタンシングのバリアントを残す必要がある追加のシェーダーです (動的に供給されるコンテンツのみで使われるシェーダーなど)。既定値は**空**です。バリアントのストリッピングが有効な場合にのみ表示されます。マテリアルではなく、必要なシェーダーアセットを追加してください。 |

> [!IMPORTANT]
> Unity 側の別設定である **BatchRendererGroup Variants** は **Keep All** のままにしてください。
> SIS の選択的なストリッピングはその後に適用されます。これらの設定によって、SIS と
> GPU Resident Drawer の同時描画がサポートされる構成になるわけではありません。

### Addressables のコンテンツビルド

Addressables は任意です。コンテンツをビルドする前に、出力する SIS シーンをベイクして
保存してください。統合された検証と DOTS バリアントのストリッピングを使うには、次の手順を
行います。

1. **Assets > Create > Addressables > Content Builders > Static Instances Packed Mode** を作成します。
2. Addressables の設定の **Build & Play Mode Scripts** にそのアセットを追加します。
3. それをコンテンツビルダーとして選択し、コンテンツをビルドします。

バリアントのストリッピングが有効な場合、Addressables がインストールされていて統合された
ビルダーがないと、Graphics パネルに情報ボックスが表示されます。統合されていない標準の
ビルダーは DOTS バリアントを残し、この SIS 固有のストリッピングは行いません。従来の
AssetBundle はこの統合の対象外です。出荷用のバンドルを作成する前に、失敗したビルドの
エラーを解消してください。

独自のビルド自動化では、基盤となるコンテンツビルドの前に
`StaticInstanceBundleStripping.BeginContentBuild(scenePaths)` を呼び出します。null 以外の
戻り値は拒否の理由なので、ビルドを中止してください。Begin やビルドが失敗した場合も含め、
`EndContentBuild()` は必ず `finally` で呼び出してください。設定画面のヒントのために
`IStaticInstanceStrippingIntegrated` を実装します。統合された検証は Scriptable Build
Pipeline (SBP) の開始前に実行されます。シーン処理のコールバックで例外を出すだけでは、
SBP のコンテンツビルドを確実に拒否できません。
